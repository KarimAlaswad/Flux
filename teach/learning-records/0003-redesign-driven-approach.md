# Teaching approach shifted to redesign-driven learning

The user's goal is not just to understand system design concepts, but to overhaul Flux — a system they recognize as a prototype built by a beginner. Lessons will now follow a pattern: teach a concept → audit Flux against it → produce a concrete redesign plan → the user implements it.

## Implications
- Each lesson must result in a tangible improvement plan for Flux
- Lessons should build on each other, progressively redesigning the system
- The audit in Lesson 2 serves as the roadmap; subsequent lessons work through it top to bottom
- Evaluation of success: does Flux actually improve, not just "does the user understand the concept"
