# Mission corrected: system design is the skill, Flux is the practice ground

Initial lesson framed the mission backward ("learn system design to build Flux") which made Lesson 1 a description of Flux's architecture with system design vocabulary as decoration. The correct framing is: the user wants to learn system design as a general skill; Flux is the concrete system we analyze and practice on together.

## Evidence
User said: "I'm not asking for describing the project, this system is a miss, I want to learn system design to apply it to this system." Confirmed "system design is the skill, Flux is the practice ground" in follow-up.

## Implications
- Lessons must teach concepts generically first, then use Flux as the exercise ground
- "Describe Flux's architecture" is never the point — the point is always the design concept
- Exercises should ask the user to *apply* a concept to Flux, not to *learn* Flux through the concept
- MISSION.md updated to reflect the correct framing
