Cordis Glossary

Reference · Living document · Updated as lessons progress

Canonical terms used throughout this teaching workspace. All lessons adhere to these definitions.

Core Concepts

Spatiotemporal Composability
The ability to dynamically compose (load, unload, reload) components at runtime with two guarantees: (1) all side effects are fully reverted on removal (temporal), and (2) inter-component dependencies are reactively managed (spatial). See also: Paper, Section 2
Temporal Composability
The "time" dimension. When a component is removed, can all of its side effects be completely reverted? A system with temporal composability guarantees no leaked listeners, timers, or state after unloading a plugin.
Spatial Composability
The "space" dimension. Can components declare what they depend on, and have the runtime reactively manage those dependencies? A system with spatial composability derives load order from declarations, not manual boot scripts.
Confluence
The property that the final system state depends only on which plugins are enabled, not the order they were loaded or unloaded. Loading A then B then removing A then re-adding A converges to the same state as loading A and B directly.

Cordis Runtime

Context (ctx)
The central Cordis object. Every plugin receives a ctx through its apply(ctx) function. It is simultaneously: (1) a dependency container (services live here), (2) a capability handle (plugins act through it), and (3) a lifecycle manager (effects and fibers are tracked here). Created via new Context() or extended via ctx.extend().
Fiber
The runtime instance of one loaded plugin. Tracks lifecycle state (PENDING → LOADING → ACTIVE → UNLOADING → DISPOSED), validated config, and all registered effects. Each plugin gets its own fiber. Fibers are children of the root fiber.
Service
A capability exposed on ctx. Services are registered under a string key (e.g., 'tools', 'llm') and resolved via the context proxy. A plugin that extends Service and is loaded as a class plugin automatically registers itself as ctx.<name>.
Registry
The plugin registry. Manages loading, unloading, and reloading of plugin fibers. Plugins can be registered as functions, constructors, or objects with an apply() method.
Effect
A side effect registered via ctx.effect(). The callback runs immediately and returns a disposer (the "inverse"). Disposers run in reverse registration order when the fiber unloads. Effects are the primitive that makes temporal composability work.
Disposable / Disposer
A function returned by an effect that releases its resources when called. Called in reverse registration order during unload. May be async.
Reactive Coeffect
A dependency declared via inject on a plugin. The runtime holds the plugin PENDING until all declared coeffects are satisfied. If a coeffect disappears mid-flight, the plugin unloads. When it returns, the plugin reloads.
Event
A named signal dispatched through the context's event bus. Supports five dispatch modes: emit, waterfall, parallel, serial, and bail. Events are the primary communication mechanism between plugins.

Fiber Lifecycle States

PENDING
Plugin declared but required dependencies (coeffects) not yet ready. The plugin's apply() has not been called.
LOADING
Dependencies are ready and apply() is executing. The plugin is initializing.
ACTIVE
The plugin is running. All effects are registered and active.
FAILED
apply() threw an error, or config validation failed. The plugin is in an error state.
UNLOADING
The plugin is being removed. Disposers are running in reverse order.
DISPOSED
The plugin is fully unloaded. All effects have been reversed.

Context Methods

ctx.extend(meta?)
Create a child context with extra metadata. The child prototypally inherits from the parent. Used for scoping.
ctx.isolate(name, label?)
Create a child context with an independent service scope for a specific service name. Different implementations can coexist in separate isolation scopes.
ctx.effect(execute, label?)
Register a cleanup-aware effect on the current fiber. Returns a disposer.
ctx.provide(name, value)
Register a service implementation owned by the current fiber. Returns a disposer that unregisters it.
ctx.on(event, handler)
Register an event listener. Automatically cleaned up when the fiber unloads.
ctx.plugin(spec)
Load a child plugin. Creates a new fiber as a child of the current one.

Glossary Rules

  • Terms are added only when the user understands them (not on first exposure)
  • Definitions are one or two sentences: what the term IS, not what it does
  • Glossary terms are preferred in all lessons and learning records
  • Ambiguous terms get explicit resolution in this workspace
